# flyToMars 脚本导航验证调整计划

## 背景

`scripts/flyToMars.ts` 用于集中模拟探索页面中用户驾驶飞船从地球飞往火星的操作体验。它不是页面运行时代码，而是一个端到端参数日志脚本，用来验证导航规划、时间跳转、推力控制和物理演化能否组合出可完成的地火飞行流程。

当前脚本已经能生成霍曼转移、执行点火和滑行，但仍有几个问题：

- 天体状态主要按当前时间即时重算，没有作为脚本全局物理状态参与每轮演化。
- 脚本维护了 `departed`、`thrustOn`、`thrustMag`、`lastPhase` 等操作状态，容易把导航流程固化成静态阶段机。
- 日志对每轮“导航给出什么、条件是否满足、实际做了什么”记录不够直接。
- 成功判定与日志中的“已到达”不完全一致，不利于判断失败原因。

## 调整目标

脚本应模拟用户操作循环，而不是通过理想轨道注入、太阳二体近似或预设结果来达到目的。全局状态包括：

- 太阳、地球、火星三个天体的状态：位置、速度。
- 飞船当前物理状态：位置、速度、推力、推力档位、船身朝向。
- 当前模拟时间与时间倍率。
- 一个最小任务阶段 `missionPhase`，用于区分“地球绕飞 / 日心转移 / 火星接近 / 到达”。它只表示用户当前所处任务进展，不保存静态路线；每轮仍必须重新生成导航指引。

每轮循环必须先让物理时间前进 `1s * timeScale`，再基于最新状态重新生成到火星的导航指引，最后判断指引条件是否满足并执行操作。不得在物理模拟前先判断是否结束。

每轮重新导航的意义是补救真实操作中的偏差：点火早/晚、熄火过冲、时间倍率过高、三体扰动、局部绕飞相位不理想等。脚本只要求最终能根据不断更新的指引到达火星，不要求第一次霍曼转移精确命中。

## 导航指引模型

每轮循环生成一个临时 `Guidance` 对象，不在循环外保存静态导航路线。指引类型包括：

- `jumpTime`：等待霍曼转移窗口。条件为地球与火星日心相位未进入窗口；操作是把天体状态和飞船状态直接跳到窗口开始时刻。
- `ignite`：需要点火。条件可来自地火窗口、火星绕飞/接近相位、轨道半长轴或速度目标。
- `cutoff`：需要熄火。条件为当前轨道或速度已达到本阶段目标。
- `turn`：需要调整方向。条件为船身朝向偏离导航要求。
- `coast`：需要滑行。条件为当前处于转移或接近阶段；操作是按距离目标的远近调整时间倍率，靠近目标时降低倍率。
- `arrived`：飞船已稳定进入火星绕飞轨道。脚本不能只用“距火星足够近”或“日心轨道接近火星轨道”作为成功条件，必须基于火星相对状态判定：火星相对机械能为负、轨道远火点处于火星希尔球安全范围内、近火点高于火星表面安全高度，并且偏心率未接近抛物逃逸。

## 物理演化约定

- 初始化使用当前真实时间对应的太阳、地球、火星状态。
- 飞船初始化为绕飞地球状态，使用现有 `createSpaceshipState('earth', ...)`。
- 天体的全局状态在每轮物理模拟后更新。对于太阳固定为原点；地球、火星使用同一时间对应的 Kepler 状态更新，以保持与页面显示和导航模块一致。
- 飞船物理演化使用现有 RK4 积分器和太阳、地球、火星三天体引力，不使用“直接设置到理想转移轨道”的捷径。
- 推力燃烧阶段使用小子步长 RK4；无推力但仍处于地球或火星引力显著区域时，使用较大的无推力 RK4 子步长继续三体推进。只有远离行星扰动的日心滑行段才允许使用 Kepler 快进。
- 火星接近段的导航目标从日心半长轴匹配切换为火星相对捕获：优先按火星相对速度反向制动，使火星相对机械能变为负；进入束缚但轨道仍过大或偏心率过高时，继续根据最新火星相对轨道要素进行修正和圆化。
- 进入火星束缚轨道后，导航必须区分当前处于近火点还是远火点附近：近火点过低时应在远火点附近顺向点火以提高近火点；远火点过大或偏心率过高时，应先滑行到近火点附近，再反向点火降低远火点。不能在远火点附近用反向点火试图降低远火点，否则会重新压低近火点并导致指引反复翻转。
- 如果转移误差使飞船只进入火星远距离接近区而尚未进入希尔球，导航应先主动削减火星相对速度，再沿火星方向进行小推力接近修正；进入希尔球后再执行火星相对制动捕获。
- 火星远距离接近区不能用单一速度阈值在“相对制动”和“朝火星接近”之间直接切换。每轮重新导航应基于当前火星相对速度、距火星变化率和正在执行的物理朝向临时判断：相对速度过高或闭合速度过快时制动，闭合速度不足或正在远离时小推力接近，速度已受控且仍在靠近时熄火滑行。该判断只来自当前物理状态，不保存循环外静态路线或操作状态。
- 速度已受控的火星远距离接近滑行，应根据当前闭合速度估算到火星希尔球外沿的剩余时间来选择时间倍率；距离希尔球仍有数十天以上时可以保持较高倍率，临近希尔球时再逐级降低，并且只在半小时级别的最终接近才降到真实时间倍率，避免既越过捕获窗口，也避免在希尔球边界外过早低倍率滑行导致循环耗尽。
- `jumpTime` 必须同时更新模拟时间、天体状态和飞船状态。等待窗口阶段飞船保持绕飞地球状态；离开地球后不再使用 `jumpTime`。
- 出发点火可以出现熄火过早/过晚，后续导航应继续根据当前轨道重新给出补救指引，例如继续顺向加速、反向修正、降低时间倍率或滑行等待。
- 离开地球 SOI 后，转移段重新导航优先检查日心远日点是否到达火星轨道半径。远日点不足时顺向补燃，远日点过高时反向修正；这用于补救出发点火时机和逃逸方向造成的实际轨道偏差。
- 地球出发段不得在飞船仍处于地球 SOI 内时用日心半长轴作为熄火条件。出发点火应按地球相对机械能和霍曼转移所需的地球逃逸双曲 excess velocity（v∞）判定，避免在地球束缚轨道内因日心瞬时轨道要素抖动而过早熄火。
- 地球出发点火还必须检查停车轨道相位。只有飞船绕飞地球的瞬时速度方向接近地球公转顺行方向时才点火；如果窗口已到但绕飞相位不合适，先按低时间倍率滑行等待相位，而不是强行把船身转到地球公转方向点火。
- 地火发射窗口采用脚本中的 `earthMarsPhase = earthAngle - marsAngle` 约定。外行星霍曼转移要求火星在出发时领先地球，因此该值应接近 `omegaMars * transferTime - π` 的归一化角，而不是相反符号。
- 等待窗口时不能一次跳过窗口。远离窗口时可跳到窗口前约一天；接近窗口后只能按较小时间片继续跳时或降低时间倍率，直到相位误差实际进入容差范围。

## 日志要求

日志写入 `scripts/flyToMars.log.txt`。每轮至少记录：

- 轮次、模拟时间、时间倍率、模拟步长。
- 太阳、地球、火星位置与速度摘要。
- 飞船位置、速度、推力、档位、船身朝向、日心半长轴、日心偏心率、距火星距离、火星相对速度、火星相对机械能、火星相对半长轴、近火点、远火点和火星相对偏心率。
- 当轮导航指引：类型、目标、触发条件、当前值、目标值、是否满足。
- 当轮实施的操作：跳转、点火、熄火、调整方向、调倍率、继续等待等。

为了避免控制台输出过大，控制台只输出关键事件和阶段性摘要；完整日志写入文件。

## 验证标准

脚本运行 `npx tsx scripts/flyToMars.ts` 应满足：

- 退出码为 0。
- 日志中包含每轮状态、导航指引、操作记录。
- 最终进入稳定火星绕飞轨道：火星相对机械能小于 0，火星相对轨道远火点处于希尔球安全范围内，近火点高于火星半径加安全高度，偏心率低于脚本定义的稳定阈值。
- 日志末尾输出 `✅ 成功进入火星绕飞轨道`，并打印火星相对轨道半长轴、偏心率、近火点、远火点、相对速度和火星希尔球半径。

如果运行失败，应分析 `scripts/flyToMars.log.txt` 中最小距离、错过窗口/目标的时间、点火/熄火条件，再调整脚本逻辑。
