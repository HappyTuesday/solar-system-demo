# 探索页地火实时导航优化计划

## 背景

`scripts/flyToMars.ts` 已验证：只要每轮都基于最新物理状态重新生成指引，飞船可以从地球绕飞轨道飞到火星，并在操作误差和修正燃烧之后进入稳定火星绕飞轨道。探索页当前仍以 `NavigationPlan + activePhaseIndex` 的静态阶段为主，`PhaseGuide` 只针对当前 phase 生成提示；当用户早一点火、晚熄火、远距离接近速度过高，或已经被火星捕获但近火点/远火点不安全时，页面不够像真实导航那样补救。

## 目标

探索页在用户选择火星为目的地后，应以“实时导航指引”为主要 UI 依据。每次渲染/物理更新都从飞船当前位置、速度、船身朝向、当前推力和当前模拟时间重新判断下一步操作，而不是信任循环外保存的静态阶段进度。

页面不直接替用户完成飞行，不通过技术手段把飞船放到火星轨道。它只给出用户可执行的指令：

- 等待地火霍曼窗口，并显示当前等待条件。时间跳转、下个月、半年等操作属于独立时间面板，不属于导航指引。
- 等待地球停车轨道顺行点火相位。
- 调整船身方向。
- 点火、熄火。
- 转移段滑行只提示当前滑行条件，不提示用户设置时间倍率。
- 出发燃烧完成后，即使飞船还没有离开地球希尔球，只要相对地球能量已为正且日心转移轨道覆盖火星轨道，实时导航也必须切换为空档滑行；不能因为旧静态阶段已完成而持续显示 `熄火`，否则真实用户会误判当前飞控动作。
- 火星远距离接近时，在相对制动、朝火星小推力接近和熄火滑行之间按当前状态切换；该接近控制区必须早于火星希尔球很多启动，且在飞船已经离开地球 SOI 后覆盖约 1.5 AU 内的近火星状态，避免飞船刚擦到旧阈值就被判回等待霍曼窗口。如果仍距火星很远且闭合速度接近下限，导航不能让用户长时间空等，应继续建议小推力接近，直到接近火星希尔球时再切换为捕获/制动指引。
- 进入火星束缚轨道后，根据火星相对轨道要素修复近火点和远火点，直到稳定绕飞。

实时指引必须把物理方向翻译成页面现有控制可执行的操作清单，至少包含船头目标方向、D/N/R 档位和推力大小。每轮 guidance 只能表达当前应执行的单个操作：`turn` 只推荐空档和零推力，等下一轮船身已对准后才给出 `ignite` 的 D 档/推力建议。火星捕获和圆化中的“相对制动/反向点火”表示船头对准火星相对逆行方向后使用 D 档向前点火，不能让用户误解为保持当前船头再切到 R 档。

为了让用户能真实执行“调整方向”指令，页面允许在导航指引面板中提供“对准导航方向”操作。该操作只把船头设置到当前实时导航计算出的目标方向，并切回惯性保持；它不设置推力、不切档、不改写位置/速度，也不跳过任何物理模拟。

为了降低火星捕获窗口中的操作误差，页面允许在导航指引面板中提供“按指引设置推力”操作。该操作只把档位和推力滑块设置为当前 guidance 推荐值，等价于用户在飞行控制面板上切档和拖动推力；它不调整方向、不改写位置/速度、不跳转时间，也不绕过物理模拟。若用户在方向未对准时应用推力，飞船仍会按当前船头真实受力，因此页面仍必须显示导航夹角和对准按钮。

导航指引面板不提供“按指引设置倍率”操作，也不显示“建议倍率”。用户如果想缩短真实等待时间，应使用独立时间面板中的“跳转到”“下个月”“半年”等时间工具；用户也可以完全不跳转时间而持续等待物理条件满足。是否跳转时间不改变导航能否最终到达火星，只改变用户实际等待多久。

为了降低右侧导航指引的信息密度，`PhaseGuide` 只保留当前阶段、操作、条件、导航夹角、对准按钮和推力按钮。详细轨道参数应迁移到画布左侧独立参数面板，供用户分析飞行过程，不与“下一步操作”混在同一个右侧面板里。

## 设计

### Engine 层

在 `src/engine/navigation.ts` 中新增纯函数实时导航 API：

- `computeLiveNavigationGuidance(input)`：根据当前飞船状态、目的地、模拟时间和船身朝向生成一个 `PhaseGuidance`，供页面直接渲染。
- `computeTargetRelativeOrbit(...)`：计算飞船相对目标天体的位置、速度、能量、半长轴、偏心率、近点、远点和距离变化率。
- `isStableTargetOrbit(...)`：判断是否已进入安全稳定的目标天体绕飞轨道。

火星目标必须使用火星相对状态判定成功：相对机械能为负、近火点高于火星半径加安全高度、远火点处于火星希尔球安全比例以内、偏心率低于稳定阈值，并且当前距离仍在稳定远火点范围内。

在 `src/engine/exploreSimulation.ts` 中集中探索页飞船物理步进：

- `computeExploreBodyStates(simulatedTime)`：按当前模拟时间生成太阳和行星的位置/速度/质量/半径。
- `advanceExploreShipPhysics(input)`：接收当前飞船状态、模拟时间、帧时间和时间倍率，按探索页同样的 RK4 子步进规则推进飞船，并返回新的飞船状态、模拟时间、行程统计和最终天体状态。

`ExploreCanvas.tsx` 只负责渲染、音效、碰撞特效和把 engine 结果写回 store，不再在组件内部维护 RK4 物理推进循环。

### 页面层

`PhaseGuide.tsx` 优先渲染 `computeLiveNavigationGuidance(...)` 的结果。旧的 `NavigationPlan`、`activePhaseIndex` 仍可作为路线背景和 MiniMap 参考，但不能作为火星捕获/圆化的唯一真相，也不能作为显示实时指引的前提。只要用户已经选择目的地且实时导航能够生成结果，页面就必须显示操作指引；当旧计划不存在或阶段不可用时，标题退化为“实时导航”。

实时导航不把 `jumpTime` 作为飞控指令。等待窗口、等待近火点和等待远火点等阶段只展示当前等待条件和目标条件。用户可以选择不跳转时间，只用正常物理推进等待；也可以通过独立时间跳转面板选择某个验证时刻。是否跳转时间只影响真实等待时长，不影响最终是否能够根据指引飞到火星。

当实时指引包含 `desiredDirection` 时，`PhaseGuide` 显示当前船头与导航方向的夹角，并提供“对准导航方向”按钮，帮助用户完成页面上本来需要用姿态按钮手动微调的方向操作。按钮必须使用最新一轮 guidance 的方向，且只能调用 store 的 `setDirection` / `setAttitudeMode('inertial')`。

当实时指引包含 `recommendedGear` 或 `recommendedThrustMagnitude` 时，`PhaseGuide` 显示“按指引设置推力”按钮。按钮必须使用最新一轮 guidance 的档位和推力建议，并且只能调用 store 的 `setThrustMagnitude` / `setGear`。对于 D/R 档，必须先设置推力大小再切档，保证 store 中的实际前后向推力与可见档位一致；对于 N 档，必须清零推力。

为避免按钮事件里分散维护操作顺序，在 `src/stores/guidanceControls.ts` 增加 store 层适配函数：

- `applyGuidanceDirection(guidance, actions)`：当 guidance 包含目标方向时，归一化方向并调用 `setDirection`，随后调用 `setAttitudeMode('inertial')`。
- `applyGuidanceThrottle(guidance, actions)`：当 guidance 包含档位/推力建议时，按页面用户操作等价顺序调用 `setThrustMagnitude` / `setGear`。D/R 档先设置推力再切档，N 档或非正推力先清零再切 N 档。
时间跳转候选时刻如果后续需要展示，应放在独立时间控制模块中，并作为验证辅助信息提供；该模块不得改变实时导航的动作语义。

`PhaseGuide.tsx` 的按钮只负责把当前实时 guidance 和 store actions 传给这些适配函数，不在组件内重复维护推力、档位和姿态切换细节。倍率和时间跳转控制留在独立时间面板，不作为导航按钮。

导航面板不得为了推进任务而提示或自动设置时间倍率，避免把时间控制误当成飞控指令。关键机动前的防越界策略应优先通过更明确的等待条件、距离/速度阈值和独立时间面板完成；导航本身只输出当前应该等待、转向、点火、熄火、捕获或圆化。

### 误差容忍

实时导航必须覆盖以下补救场景：

- 出发燃烧不足：转移远日点低于火星轨道时提示顺向补燃。
- 出发燃烧过量：转移远日点明显高于火星轨道或日心轨道已成双曲线时，若仍在点火必须先提示熄火；熄火后再提示对准日心逆行方向并反向修正。不能在过燃后继续提示顺行补燃。
- 出发燃烧刚完成且仍在地球希尔球内：若已逃逸地球并且日心轨道已经覆盖火星轨道，应立即提示转移滑行，而不是继续用旧阶段完成态提示熄火。
- 火星远距离接近相对速度过高：提示沿火星相对速度反向制动；接近火星希尔球外沿时，即使闭合速度不高，只要相对速度仍高于捕获释放速度，也必须提前切入制动。
- 接近火星希尔球外沿且火星相对机械能仍为正时，继续提示制动，不能仅因固定速度阈值以下就滑行。
- 进入火星希尔球近旁且火星相对机械能已经为负时，远距离接近逻辑必须让位给火星捕获/圆化修复逻辑，避免弱束缚高偏心轨道被长期判为“远距离速度受控滑行”。
- 火星远距离制动/接近中，如果当前推力已经开启但船头偏离推荐方向，应先提示熄火，再重新对准；不能在错误方向推力持续时继续提示捕获制动。
- 地火行星距离变近但飞船仍在地球停车轨道：必须继续使用地球出发指引，不能仅凭“距火星小于远距离控制阈值”切到火星相对制动。
- 火星远距离闭合速度不足、接近下限或正在远离：提示朝火星小推力接近；只有闭合速度已经明显受控时，才提示熄火滑行。
- 已被火星捕获且处于火星希尔球近旁/内部后，若近火点过低：先滑行到远火点，再顺向点火提高近火点。希尔球外的弱负相对能量不能直接当作稳定捕获。
- 已被火星捕获且处于火星希尔球近旁/内部后，若远火点过大或偏心率过高：先滑行到近火点，再反向点火降低远火点。希尔球外仍按远距离接近/制动处理。
- 已满足稳定火星绕飞：提示导航完成并停止要求推力。

## 验证

- 新增 engine 单元测试覆盖稳定火星绕飞识别、近火点过低修复、远火点过大修复、远距离接近模式选择。
- 新增 engine 单元测试覆盖出发燃烧完成但仍在地球希尔球内的逃逸滑行状态，确保实时导航给出 `coast`，不被旧阶段 completed fallback 压成 `cutoff`。
- 新增 engine 单元测试覆盖探索页物理步进函数，确保它使用飞船当前方向、D/N/R 档位对应的体坐标推力、时间倍率和移动天体状态来推进飞船。
- 新增 store 层适配测试覆盖“对准导航方向”和“按指引设置推力”的调用顺序，确保页面按钮只等价执行用户控制，不改写位置/速度/时间；组件测试覆盖导航面板不显示倍率指引，并且详细轨道参数已迁移到左侧参数面板。
- 新增 store/engine 集成测试：使用真实 `spaceshipStore`、`exploreStore`、实时导航、页面控制适配函数和 `advanceExploreShipPhysics` 模拟用户每轮先物理推进、再根据最新指引操作，验证从地球绕飞轨道最终进入稳定火星绕飞轨道。
- 运行 `npx vitest run src/engine/__tests__/navigation.test.ts`。
- 运行 `npm run build` 进行 TypeScript 和生产构建验证。
- 保留脚本回归验证：`npx tsx scripts/flyToMars.ts` 应继续成功进入火星绕飞轨道。
