# 探索页地火导航指令系统设计

## 背景

当前探索页的地火导航把静态 `NavigationPlan`、实时 `computeLiveNavigationGuidance`、页面按钮行为混在一起使用。浏览器验证中已经暴露出两个系统性问题：

- “快进到发射窗口”依赖旧 plan 的 `expectedWaitDays`，跳转后可能仍然处于长时间等待窗口，导致用户反复跳未来日期却无法进入点火指引。
- 飞船出发燃烧完成后，旧阶段的 `completed` fallback 可能持续显示“熄火 + 1x”，压住真正应该出现的转移滑行高倍率指引。

这些问题说明页面缺少一个明确的飞行指挥层。后续导航必须以当前物理状态为唯一依据，每轮重新生成当前操作建议，而不是维护一份会过期的全局飞船操作状态。

## 核心原则

导航系统只回答一个问题：**基于当前太阳、地球、火星和飞船状态，用户现在应该做什么，为什么。**

导航不得把飞船直接放到目标轨道，不得为了成功而改写位置或速度。用户操作只允许通过页面已有控制等价执行：

- 对准船身方向。
- 设置档位。
- 设置推力。
- 继续等待。

`jumpTime` 不是导航成功的必要步骤，也不是导航强制执行的动作。用户可以选择不跳转时间，用 `1x` 或任意倍率等待物理条件满足；也可以选择在某个时刻使用时间跳转来验证后续阶段。是否跳转时间只影响真实等待时长，不影响最终是否能够根据导航飞到火星。

当霍曼窗口条件已经满足时，窗口等待提示只能作为已完成状态记录，不能继续占用导航主指令。实时导航必须立即重新规划当前飞船状态，并切换到地球绕飞点火相位、出发方向调整或出发点火等后续指令，避免页面停留在“窗口已就绪”而无法进入真实出发操作。

地球出发过燃修正需要区分“错误方向仍在推力中”和“已经对准修正方向并正在反向修正”。如果飞船已经对准日心逆行修正方向并按推荐推力工作，导航必须维持反向修正点火指令，直到日心轨道重新落回可到达火星的范围；不能因为 `thrustMagnitude > 0` 就无条件要求熄火。只有推力方向与修正方向明显偏离时，才应先熄火再重新对准。

页面导航面向人的真实操作，不能默认使用理论上最快但人工不可控的最大推力。地球出发、地球补燃和过燃反向修正应使用低推力连续修正，让用户有足够时间观察导航刷新并执行熄火或方向调整。最大推力只适合自动积分测试或已经进入明确需要强制动的阶段，不能作为默认人工出发指令。

浏览器验证表明，即使物理引擎在有推力时把单帧模拟步长限制为 `0.02s`，真实用户点击按钮、等待 UI 刷新、读取指引仍会消耗数秒真实时间。地球出发 `5 MN` 和过燃修正 `10 MN` 在这段反应时间内会越过目标；进一步降到 `1 MN` 后，页面实测 6-10 秒延迟仍会把远日点推到 10 AU 以上。因此地球离场阶段的默认人工指令应使用 `0.2 MN` 量级的亚 MN 低推力，以“可连续观察、可及时熄火”为优先目标；若后续要提高效率，应通过导航根据剩余能量/远日点误差分级升降推力，而不是恢复固定大推力。

地球出发分为三个方向控制阶段：尚未逃逸地球时，点火方向使用地球相对绕飞顺行方向；刚获得地球相对正能量但仍在地球希尔球深处、逃逸裕度不足时，继续保持地球相对顺行，避免过早切换方向导致重新被地球束缚；已经稳定离场但日心轨道尚未覆盖火星轨道时，补燃方向才切换为绕太阳的局部切向顺行方向，而不是飞船当前日心速度方向。飞船刚逃逸地球时速度仍混有很强的近地径向分量，沿当前速度或过早沿日心切向补燃都可能把地球相对能量拉回负值。若补燃推力已开启但船头偏离当前阶段推荐方向，应先熄火、重新对准，再继续低推力补燃。

地球希尔球深处不能用瞬时日心远日点直接判定出发过燃。低轨顺行点火时，飞船日心速度会临时叠加约 7.7 km/s 的地球绕飞速度，瞬时日心 osculating 轨道可能显示远日点远超火星轨道，但这部分速度会在离开地球势阱时转化为地球相对双曲 excess。地球离场阶段应优先以火星霍曼转移所需的地球相对 `v∞` 能量作为点火/熄火条件；只有离开地球近场并稳定离场后，才用日心近日点/远日点覆盖判断转移轨道质量。

页面实测还表明，如果导航等到理论 `v∞` 能量完全达到后才提示熄火，真实点击和 UI 刷新延迟会把出发能量推高，形成半长轴约 `1.34 AU`、远日点约 `1.69 AU` 的偏高转移轨道，首次交会会错过火星。人工导航应提前在目标 `v∞` 能量约 80% 以上提示熄火，把剩余能量增长留给人的反应时间；若提前量不足，后续实时导航再进行小幅补燃或修正。

地球出发过燃修正的优先级必须高于“轨道覆盖火星后滑行”。真实页面操作中，用户看到熄火提示、移动鼠标并点击按钮会产生数秒到数十秒延迟；这期间可能仍然满足“覆盖火星轨道”，但远日点已经被推到远超火星轨道。导航若先返回滑行，就会把可补救的过燃误判为正常转移。只要飞船已经获得地球相对正能量，且日心轨道明显过量或接近双曲线，就必须先进入过燃熄火/逆行修正流程，再允许恢复转移滑行。

一旦飞船已经相对地球机械能为正，导航不得再用“等待地球绕飞点火相位”阻塞后续指引。地球绕飞相位只对仍被地球束缚的停车轨道出发有效；逃逸后的补燃属于日心转移修正，必须依据日心远日点覆盖、日心偏心率和船头相对日心顺行/逆行方向重新规划。

导航按钮不能只执行一次性的惯性对准。真实用户按下“对准导航方向”后，若指引方向是“当前绕飞顺行方向”，页面应进入地球相对顺向保持；若指引方向是“日心切向顺行补燃方向”，页面应进入日心切向顺行保持；若指引方向是“日心逆行修正方向”，页面应进入日心逆向保持。否则飞船在逃逸边界附近会因为方向快速变化而在用户下一次点击前偏离。

当飞船刚逃逸地球且日心轨道已经覆盖火星轨道时，导航应优先给出转移轨道建立后的熄火/滑行指令。即使此时地火距离小于火星远距离接近阈值，也不能提前进入火星相对制动；火星接近控制只能在飞船已经离开地球离场区后接管。

火星远距离接近控制区不能覆盖 1 AU 量级的日心转移巡航。只有飞船已经进入火星附近的局部接近区后，才允许启用火星相对速度制动和小推力接近逻辑；否则应继续使用转移巡航或重新规划的日心转移指引，避免在远离火星时过早制动导致轨道发散。

## 导航输出模型

新增导航指令模型 `NavigationDirective`，用于替代页面直接消费旧 `PhaseGuidance`。

```ts
type DirectiveAction =
  | 'wait'
  | 'turn'
  | 'ignite'
  | 'cutoff'
  | 'coast'
  | 'capture'
  | 'circularize'
  | 'arrived';

interface NavigationDirective {
  action: DirectiveAction;
  title: string;
  target: string;
  reason: string;
  condition: {
    label: string;
    current: number;
    target: number;
    unit: string;
    satisfied: boolean;
  };
  desiredDirection?: [number, number, number];
  desiredDirectionLabel?: string;
  recommendedGear: 'D' | 'N' | 'R';
  recommendedThrustMagnitude: number;
  suggestedTimeScale: number;
  metrics: NavigationMetric[];
}
```

指令中不包含 `jumpTime` 或 `jumpTargetTime`。等待窗口、等待近火点、等待远火点等场景都用 `action: 'wait'` 或 `action: 'coast'` 表达，并明确列出等待的物理条件。

## 时间控制模型

时间控制从导航指令中拆出，成为独立的用户工具：

- 时间倍率按钮只改变 `timeScale`。
- 探索页默认时间倍率为 `1x`，避免用户尚未主动加速时错过点火、熄火、捕获等关键操作窗口。
- 时间跳转面板只调用 `timeJump(targetTime)`。
- 导航可以显示“当前等待条件”，例如地火日心夹角、地球绕飞相位、距近火点差、距火星距离。
- 导航面板不得显示“建议倍率”或“按指引设置倍率”按钮。是否加速等待、跳到下个月、跳到半年后或保持真实时间等待，都是用户在独立时间面板中的选择，不属于飞行指令。

如果后续需要“跳到验证时刻”，应由独立时间面板提供候选时间，例如：

- 下一个地火窗口附近。
- 下一个地球绕飞点火相位附近。
- 预计进入火星远距离接近区附近。
- 预计近火点或远火点附近。

这些候选时间是辅助验证工具，不属于导航指令动作。即使用户完全不使用这些候选时间，只要持续物理推进并按指令操作，飞船也必须能到达火星。

## 飞行阶段分类

导航每轮从当前物理状态即时分类，不读取旧 `activePhaseIndex` 作为控制依据。

火星任务启用实时 `NavigationDirective` 后，旧 `navigationPlan` 只能作为左侧路线概览，不得再参与飞船控制闭环。`checkNavigationalDeviation` 不能因为旧阶段完成、偏离或重规划而清零推力、切换阶段、改写档位或覆盖当前指令；否则用户刚按下实时导航的 D 档 1 MN 点火按钮，就可能被旧阶段检查立即清成 D 档 0 MN，导致页面看似点火但飞船实际没有推力。

### 1. 地球停车轨道等待

条件：

- 飞船仍被地球束缚。
- 目标为火星。
- 尚未到地火霍曼转移窗口，或地球绕飞相位未到点火窗口。

输出：

- `action: 'wait'`
- `gear: 'N'`
- `thrust: 0`
- 指明等待条件：地火日心夹角，或地球绕飞点火相位。
- 等待说明只能描述物理条件，不提示用户调整时间倍率；时间倍率和时间跳转属于独立时间工具。

### 2. 地球出发点火

条件：

- 地火窗口满足。
- 地球绕飞相位接近顺向出发点。火星任务人工导航使用 90° 附近的窄窗口，例如 80°-100°；过宽的 30°-150° 会让页面在 40° 左右提示点火，真实操作会把日心速度降得过低，后续补燃难以补救。
- 当前地球相对顺行方向必须与地球绕太阳公转方向同向。仅靠 0°-180° 的相位夹角无法区分两个 90° 点；错误一侧的“顺行”会抵消地球日心速度，使日心速度降到约 21 km/s，不能作为火星外行星转移出发点。
- 飞船仍未获得足够地球逃逸能量，或日心转移轨道尚不能覆盖火星轨道。

输出：

- 未对准：`action: 'turn'`，`gear: 'N'`，`thrust: 0`。
- 已对准：`action: 'ignite'`，`gear: 'D'`，推荐出发推力。
- 条件指标包含地球相对能量、日心远日点、目标火星轨道半径、当前船身夹角。

### 3. 日心转移滑行

条件：

- 飞船相对地球能量为正，或已离开地球希尔球。
- 日心轨道的近日点/远日点范围覆盖火星轨道。
- 当前火星交会预测可接受，预计最近距离能够进入火星远距离接近控制区。
- 尚未进入火星远距离接近控制区。

输出：

- `action: 'coast'`
- `gear: 'N'`
- `thrust: 0`
- 只说明当前为物理滑行/等待，不提示用户修改倍率。
- 不能因为仍在地球希尔球内而退回“等待发射窗口”。

仅仅“日心轨道半径覆盖火星轨道”不能证明飞船会在正确时间靠近火星。实时导航必须同时评估飞船相对火星的位置、相对速度、闭合速度、预计最近接近时间和预计最近距离。若轨道覆盖火星但预计最近距离仍大于火星远距离接近控制区，或者飞船正在远离火星，导航不得长期保持纯滑行，必须进入日心转移巡航交会修正。

### 3.1 日心转移巡航交会修正

条件：

- 飞船已经离开地球出发控制区，且目标为火星。
- 尚未进入火星远距离接近控制区。
- 日心轨道大致覆盖火星轨道，或飞船已经处在火星轨道半径附近。
- 基于当前火星相对位置/速度预测，最近接近距离仍大于火星远距离接近控制区，或当前距离率显示飞船正在远离火星。

输出：

- 当前仍在错误方向点火：`action: 'cutoff'`，先熄火。
- 未对准：`action: 'turn'`，船头对准日心巡航交会修正方向。
- 已对准：`action: 'ignite'`，D 档低推力修正。

修正方向以“下一轮重新导航后能持续降低火星相对错过量”为目标，而不是一次性精确命中理论轨道。基础策略是沿指向火星方向建立闭合趋势；当飞船已经接近且相对速度过高时，由火星远距离接近和捕获阶段接管制动。该阶段必须使用可人工操作的低推力，让用户即使点火偏早、熄火偏晚，也能依靠后续每轮实时导航继续补救。

轻微偏高的日心椭圆仍属于巡航交会修正的处理范围。例如人工熄火延迟导致远日点略高于火星轨道时，导航不能因为“远日点超过标准霍曼目标”就排除中途修正，否则飞船会在多次绕日后持续错过火星。只有双曲线或远日点极端过量的轨道才交给地球出发过燃修正或后续重新离场流程。

如果用户执行巡航交会修正时点火过久，导致日心轨道不再覆盖火星轨道，导航必须优先给出“先熄火”的保护指令，再由下一轮从当前物理状态重新规划补救动作。不能在推力仍开启时退回旧的发射窗口等待提示，否则页面会继续沿错误方向点火。

### 3.2 地球出发过燃修正

条件：

- 飞船已经逃逸地球。
- 日心轨道没有覆盖火星轨道，且轨道已经过量，例如日心轨道为双曲线，或远日点明显越过火星轨道。
- 当前仍在点火，或船身没有对准日心逆行修正方向。

输出：

- 若当前仍在点火且方向不是修正方向：`action: 'cutoff'`，先熄火，避免继续把误差放大。
- 熄火后未对准：`action: 'turn'`，船头对准日心逆行修正方向。
- 对准后：`action: 'ignite'`，D 档按推荐推力反向修正，直到日心轨道重新覆盖火星轨道。

该阶段用于补救真实页面操作中的点火过晚、熄火延迟和按钮响应误差。导航不能在已经过燃时继续提示顺行补燃。

### 4. 火星远距离接近

条件：

- 距火星进入远距离控制区，例如 `<= 1.5 AU`。
- 尚未稳定进入火星束缚轨道。
- 飞船已经完成地球出发：不再被地球束缚，且当前日心转移轨道已经覆盖火星轨道。仅仅因为地球与火星在行星会合中距离小于 1.5 AU，不能把仍在地球停车轨道内的飞船判定为火星接近。

输出根据当前火星相对状态动态选择：

- 当前推力已开启但船头没有对准推荐制动/接近方向：先 `cutoff`，避免继续沿错误方向加速。
- 相对速度高于捕获目标速度：对准火星相对逆行方向，点火制动。远距离接近阶段不能把 `0.8-0.9 km/s` 这类仍明显高于目标的速度判定为“受控滑行”，否则飞船会在进入希尔球前保持正能量并掠过火星。
- 接近火星希尔球外沿且相对火星机械能仍为正：继续制动，即使闭合速度看起来不高。
- 进入火星希尔球近旁且相对火星机械能已经为负：退出远距离接近控制，交给火星捕获/圆化修复逻辑处理近火点和远火点。
- 闭合速度不足或正在远离：对准火星方向，小推力接近。
- 接近速度受控：空档滑行。若仍在希尔球外很远，可以快速滑行；接近希尔球和捕获窗口前必须逐级降倍率，避免越过制动时机。

### 5. 火星捕获

条件：

- 接近火星希尔球外沿或内部。
- 火星相对能量仍为正，或相对速度明显高于可捕获范围。

输出：

- 对准火星相对逆行方向。
- `gear: 'D'`
- 推荐捕获制动推力。
- 关键窗口必须自动建议低倍率，避免越过捕获时机。

### 6. 火星绕飞修复

条件：

- 火星相对能量为负，但轨道不稳定。

输出：

- 近火点过低：滑行到远火点，再顺向点火抬升近火点。
- 远火点过高：滑行到近火点，再逆行点火降低远火点。
- 偏心率过高：根据当前近火点/远火点位置选择修复机动。

火星束缚轨道修复的等待时间可能以数天到数月计。自动验证和内部安全倍率可以在远离近火点/远火点时快速滑行，但必须随着距目标拱点变小逐级降倍率，确保页面在点火窗口前重新给出低倍率、可人工执行的方向和推力指引。页面仍不得把倍率设置作为导航主操作展示给用户。

### 7. 稳定火星绕飞

条件：

- 火星相对能量为负。
- 近火点高于安全高度。
- 远火点处于火星希尔球安全比例以内。
- 当前距离仍在稳定绕飞范围内。

输出：

- `action: 'arrived'`
- `gear: 'N'`
- `thrust: 0`
- 页面显示“已进入稳定火星绕飞轨道”。

## 模块边界

### `engine/marsMissionNavigator.ts`

纯逻辑模块，输入当前物理状态，输出 `NavigationDirective`。

职责：

- 计算太阳、地球、火星、飞船的相对状态。
- 分类当前任务阶段。
- 生成唯一当前指令。
- 计算指令指标和原因。

不得：

- 读写 Zustand store。
- import React 或 Three.js。
- 调用 `timeJump`。
- 维护“已经执行过哪些操作”的全局状态。

### `engine/exploreSimulation.ts`

继续作为探索页物理推进层。

职责：

- 每帧先按当前时间倍率推进真实物理。
- 推进太阳、地球、火星等天体状态。
- 根据飞船当前方向、档位和推力推进飞船状态。

### `stores/guidanceControls.ts`

用户操作适配层。

职责：

- `applyGuidanceDirection(directive, actions)`
- `applyGuidanceThrottle(directive, actions)`
- `applyGuidanceTimeScale(directive, actions)`

这些函数只能调用等价用户操作，不能改写位置、速度或模拟时间。

### `PhaseGuide.tsx`

渲染层。

职责：

- 渲染当前 `NavigationDirective`。
- 显示等待条件、推荐方向、推荐档位、推荐推力。
- 提供“对准导航方向”“按指引设置推力”按钮。
- 保持右侧导航面板聚焦“下一步飞控动作”，不渲染详细轨道参数。

不得：

- 用旧 `NavigationPlan` 决定当前操作。
- 在组件中计算复杂轨道逻辑。
- 把 `jumpTime` 当作导航动作。
- 把 `suggestedTimeScale` 展示成飞行指引，或提供导航倍率按钮。

### `FlightParametersPanel.tsx`

左侧飞行参数面板。

职责：

- 渲染详细轨道参数、距目标距离、相位角、逃逸能量、速度分量等分析数据。
- 使用 engine 层纯函数计算参数，组件只负责读取 store 和展示。
- 与右侧 `PhaseGuide` 并列显示，避免导航指引被分析数据淹没。

不得：

- 提供飞控按钮。
- 修改飞船位置、速度、推力、档位、时间或导航计划。

### 时间跳转面板

时间跳转功能应独立于导航面板。

职责：

- 允许用户选择任意验证时刻。
- 可显示导航计算出的候选物理时刻，但用户不使用也不影响可达性。
- 调用 `timeJump` 后，下一帧导航必须基于新物理状态重新生成指令。

## 旧系统降级

`NavigationPlan + activePhaseIndex` 不再作为飞控依据。它可以保留为路线背景和 MiniMap 参考：

- 展示大致阶段。
- 绘制参考转移轨道。
- 帮助用户理解总体路线。

但页面按钮、当前操作、推力建议、倍率建议、到达判定，必须来自 `NavigationDirective`。

## 日志与验证

页面和脚本验证都应记录同一种飞行参数日志：

- 模拟时间。
- 天体状态：太阳、地球、火星位置和速度。
- 飞船状态：位置、速度、方向、推力、档位、时间倍率。
- 当前 `NavigationDirective`。
- 用户执行的页面操作。
- 操作后下一轮物理状态。

验证标准：

- 不使用 `timeJump`，只使用高倍率等待，也能最终根据指令到达火星。
- 使用 `timeJump` 跳到某些验证时刻后，下一轮导航仍能从当前状态恢复并继续完成任务。
- 出发点火早/晚、熄火早/晚后，实时导航能补救。
- 火星远距离接近不会长期低倍率空等。
- 火星捕获后能修复近火点和远火点。
- 最终进入稳定火星绕飞轨道。

## 测试计划

- Engine 单元测试覆盖每个阶段分类和指令输出。
- Store 测试覆盖指令到用户操作的适配顺序。
- 集成测试模拟“每轮先物理推进，再读取最新指令，再执行用户操作”。
- 集成测试必须包含不使用 `timeJump` 的路径。
- 额外测试允许使用 `timeJump` 跳到验证时刻，但不能把它作为成功的必要条件。
- 浏览器验证只点击页面按钮，不直接调用 store 或改写物理状态。
